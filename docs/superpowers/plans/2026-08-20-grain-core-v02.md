# Granular Freeze v0.2 Grain Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the prototype frozen-loop reader with a deterministic, real-time-safe granular engine controlled by Size, Density, Position, and the existing Pitch parameter.

**Architecture:** Keep host integration, capture, state, and live/granular transitions in `GranularFreezeAudioProcessor`; move chronological frozen-buffer reads and all grain voice/scheduler work into an isolated `GrainEngine`. Render grains into a preallocated stereo scratch buffer, then blend it with live input in one sample-major processor loop so shared state advances once per sample rather than once per channel.

**Tech Stack:** C++17, JUCE 8.0.15, CMake 3.22+, AU/VST3, custom offline console-test harnesses, GitHub Actions on macOS and Windows.

**Spec:** `docs/superpowers/specs/2026-08-20-grain-core-v02-design.md`

## Global Constraints

- Keep the APVTS root exactly `PARAMS`.
- Preserve IDs, ranges, defaults, and meanings for `freeze`, `pitch`, and `crossfadeMs`.
- Add exactly `grainSizeMs` (`5`-`200`, default `80`), `densityHz` (`0`-`200`, default `20`), and `position` (`0.00`-`1.00`, default `1.00`).
- Keep stereo input equal to stereo output; do not add mono, MIDI input, MPE, or new bus layouts.
- Keep the fixed capture capacity at eight seconds.
- Use exactly 64 preallocated grain voices, shared event timing and read positions across stereo channels, Hann windows, cubic interpolation, and envelope-weighted overlap normalization.
- Perform no allocation, resize, file/network/console I/O, lock, wait, random-device access, or unbounded scheduler catch-up inside `processBlock` or `GrainEngine::render`.
- Read and clamp parameter values once per host block. Size, Position, and Pitch are launch-time voice values; Crossfade is captured when a transition starts.
- Build with CMake 3.22+ and JUCE 8.0.15; keep AU and VST3 packaging on macOS and VST3 packaging on Windows.
- Do not add feedback, scatter, time-stretch, presets, waveform UI, licensing, pricing, signing, tags, releases, or store integration.
- Treat rendered WAV files as listening aids, not CI pass/fail evidence.
- Do not claim release readiness until Gabriel performs the Ableton Live or Bitwig listening gate.

Invalid channels, metadata, or non-finite positions return zero. Do not allocate or create a temporary buffer.

struct GrainParameters

class GrainEngine

    void prepare (double newSampleRate) noexcept;

private:

    {

        double logicalReadPosition = 0.0;
        double sourceIncrement = 1.0;
        int envelopeIndex = 0;
        int envelopeLength = 2;
        std::uint64_t launchOrder = 0;
    };
    void launchVoice (const FrozenBufferView&, const GrainParameters&) noexcept;
    static GrainParameters sanitise (GrainParameters) noexcept;
    std::array<Voice, maxVoices> voices {};
    double sampleRate = 44100.0;
    double samplesUntilNextLaunch = 0.0;
    double currentLaunchInterval = 0.0;
    bool schedulingEnabled = false;
    std::uint64_t nextLaunchOrder = 0;
    std::uint64_t totalLaunchCount = 0;
};

- [ ] **Step 4: Implement launch position and scheduler**

Clamp values to the approved ranges. Calculate launch state with:

```cpp
const int grainSamples = juce::jmax (2, juce::roundToInt (
    parameters.grainSizeMs * 0.001f * (float) sampleRate));
const int sourceSpan = 1 + (int) std::ceil (
    (double) (grainSamples - 1) * (double) parameters.pitch);
const int maxCompleteStart = source.span - sourceSpan;
const double logicalStart = maxCompleteStart >= 0
    ? std::round ((double) parameters.position * (double) maxCompleteStart)
    : std::round ((double) parameters.position * (double) (source.span - 1));
```

Use the first inactive voice, or deterministically replace the smallest `launchOrder`. Increment the count only for a readable-source launch. Positive Density uses `max(1.0, sampleRate / densityHz)`. Zero-to-positive sets countdown to zero; interval changes clamp the remaining countdown; each sample launches at most once. Density zero disables scheduling and lets active voices finish.

`prepare()` accepts a finite positive sample rate or falls back to `44100.0`, then calls `reset()`. `reset()` deactivates every voice and zeros the countdown, interval, scheduling flag, launch-order counter, and total-launch counter. `getActiveVoiceCount()` performs one bounded scan of the 64-voice array.

- [ ] **Step 5: Implement shared stereo rendering**

For each sample and active voice compute:

```cpp
const double phase = (double) voice.envelopeIndex
                   / (double) (voice.envelopeLength - 1);
const float weight = 0.5f - 0.5f * std::cos (
    juce::MathConstants<float>::twoPi * (float) phase);
```

Read both channels at the same logical position, add the weight once, then advance the voice once. Divide both channel sums by `juce::jmax(1.0f, weightSum)`, replace non-finite output with zero, and write to the pre-existing destination region. Clear the region first. Do not resize, allocate, log, or use a catch-up loop.

        const float inputR = buffer.getSample (1, offset + i);

            inputL * (1.0f - currentMix) + wetScratch.getSample (0, i) * currentMix);

            inputR * (1.0f - currentMix) + wetScratch.getSample (1, i) * currentMix);

}
