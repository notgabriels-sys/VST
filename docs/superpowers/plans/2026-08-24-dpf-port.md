# Granular Freeze DPF Port Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace JUCE host integration with a zero-framework-fee DPF implementation that builds equivalent VST3, AU, and CLAP plug-ins.

**Architecture:** A standard-C++ DSP core owns all musical behavior and is exercised without any plug-in framework. Thin DPF DSP and DGL UI adapters expose the stable host contract. CMake fetches one immutable DPF revision and its tree-pinned UI submodule.

**Tech Stack:** C++17, CMake 3.22+, DPF/DGL, CTest, GitHub Actions

**Spec:** `docs/superpowers/specs/2026-08-24-dpf-port-design.md`

## Global Constraints

- Preserve all seven parameter symbols, order, ranges, steps, defaults, and meanings.
- Stereo input and output only; no MIDI.
- Audio callback performs no allocation, locking, I/O, or unbounded work.
- DPF commit is `4238e1c7f0351bbe488d79f0899c540543ac7583`; Pugl submodule commit is `5e2621d714ddf1cb0f86e852f8ba5dffe04aa3a3`.
- Build VST3/CLAP on macOS and Windows, plus AU on macOS.
- Preserve the JUCE implementation only in Git history/private reference state; do not publish or relicense it.
- Do not create a tag, public release, store product, or paid credential requirement.
